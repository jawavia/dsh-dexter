## 2026-11-14 · 一天之内从"改造"到"可用"

### 1. 定调：不是新插件，是 click-matrix 的升级版

- 底层注入**不重写**：pixel 引擎（`dsh-click-matrix`）与 UIA 引擎（`dsh-x2`）保留，作为 backend 装载；
- 中间换掉的是**治理层**：闸门（授权）、审计、FSM、路由、验证；
- 对外工具从旧包的 14 个收成 **4 个**：`hands_view / hands_act / hands_run / hands_status`。

### 2. 关键数字（可复算）

| 指标 | 旧 `dsh-click-matrix` | `dsh-dexter` | 算法 |
|---|---|---|---|
| 工具数 | 14 | 4 | `tools/measure-surface.mjs` |
| 工具面体积 | 20,370 B | 7,034 B | 同上 |
| 每请求上下文 | ≈5,134 tokens | ≈1,706 tokens | `tools/compare-pixel.mjs` |
| 点击延迟 | 289.8ms / p95 304.3 | 283.4ms / p95 293.9 | 同上（18 次点击 + 12 探针的夹具） |
| 审计粒度 | 3 行/次点击、悬停不记 | 4 行/次点击、悬停也记 | 引擎审计 vs 本插件审计 |

**结论**：注入速度打平（Δ −6.4ms 属噪声）；省的是上下文与"人工往返次数"。

### 3. 自包含（D2 改写）

两个引擎 vendor 进包：`vendor/pixel`（dsh-click-matrix 0.9.5 + schemastery/cosmokit/@standard-schema）、
`vendor/uia`（dsh-x2 0.6.0-local.1 + koffi 3.3.6/@koromix，含原生 `koffi.node`），全部未修改的 MIT 代码，
许可证随包。解析顺序：显式配置 → `vendor/` → `DSH_DEXTER_LEGACY_ROOT` → `local.config.json` → 已安装包。

**验证**：克隆到空目录（无 `local.config.json`）后 `run-all` 全绿；`test/09` 在隐藏本地配置的情况下
启动整个插件并断言审计行写 `backends came from vendor`。

### 4. 授权：从"开一次管到底"到有界会话

- 默认 15 分钟 / 100 次 / 30 每分钟，到期回落逐次请示；
- 三个数字是**唯一**可调参数，声明在 `kernel/config.js` 的 `FIELD_SPEC`（`test/03` 盯着"只声明一次"）；
- 面板右键可加减（`授权时长 ±5 分` / `次数 ±50` / `频率 ±10` / 恢复默认），立即生效；
- 系统类目标（注册表、任务管理器、杀软、凭据管理器、管理员窗口）**内核永久拒绝**，任何授权不覆盖；
- 私人目标（聊天/邮件/支付/密码）即使有会话也**逐条请示**；
- `move` 悬停免授权但留痕、限速，鼠标键按住时拒绝；
- 批量 `hands_run` **按步扣额度与频率**，余额不足整批拒绝。

### 5. 审计

- 单一哈希链（`seq` / `prev` / `h`），一条文件：`~/.dsh/dexter/audit/hands.jsonl`；
- 今天修掉一个真问题：插件重载时旧实例还在写 `helper/exit`，两个计数器互插 → 4 处断链。
  修法：每次写前核对文件大小，被别人动过就重新对齐链头（`e4a21cd`，`test/11` 7 项）。

### 6. 热键：把 F12 真正接管回来（D14）

**问题**：pixel 引擎的 helper 把 `Ctrl+Alt+F12` 硬编码给自己那个本插件并不使用的闸门，所以按 F12
只会开引擎的闸门，**本插件仍然无授权**；状态行还把它报成"被占用"（占用者是我们自己的 helper）。

**做法（人选的 B 方案）**：

- 新增 `ui/Hotkeys.cs`：隐藏的 WinForms 消息泵（`WS_EX_TOOLWINDOW`，不进任务栏/Alt+Tab，不显示窗口），
  `RegisterHotKey` 四个 id，每按一次往 stdout 打 `event arm`；
- `kernel/hotkeys.js`：编译（系统自带 csc）、启动、解析协议、映射到与按钮/命令**同一条**动作链；
- vendor 的 `runtime/helper.cs` 加一个环境开关：`DSH_DEXTER_HOTKEYS=arm` 只让出 arm 那一个组合；
  **急停（F11）与软停（Shift+F11）仍归引擎**——监听进程崩溃也不会失去停止通道；
- 测试进程设 `DSH_DEXTER_NO_HOTKEYS=1`，绝不偷真实热键（第一版没设，测试把 F12 抢走了）。

**验证**：向监听窗口 `PostMessage(WM_HOTKEY, id=1)`，审计立刻出现
`gate · grant-opened` + `hotkey · input · arm`；随后用户**物理按 F12**，授权在面板与 `hands_status` 上同步出现。

### 7. 设置页：三次尝试，最后落在面板

1. 让三个字段 `.volatile()` —— DSH 的设置页确实只渲染 volatile 字段，但**这个版本没有通用表单渲染器**
   （`dsh-settings` 原文："Forms expose only volatile fields… no shipped client does so yet"）；
2. 自己注册 `settings.plugins.tab` 页签（照 `dshmarket` 的写法）——页签能注册，但写配置时宿主
   `config-editor` 拒绝嵌套 include（`HMR transactions cannot be nested`）；
3. **最终方案**：配置放**面板菜单**，值写进 `runtime-overrides.json`（`kernel/overrides.js`），
   优先级：面板/命令覆盖 > 宿主配置 > `FIELD_SPEC` 默认值。`/dexter set` 改同一层。

### 10. 没做到的 / 明确留着的

- 跨机、多屏、DPI 变化未验证（本机只有一块 2880×1800@2x）；
- 目标识别是"进程名 + 标题子串"，改名程序可能漏判；
- **读不受闸门约束**（截图/UIA 能读凭据管理器窗口）；
- `focus` 会改前台（有审计行，不占写授权）；
- Esc 不能注入（它是急停通道），所以菜单要用点击关闭；
- 面板崩溃不自动重启（避免把"我主动退出"当崩溃）。
