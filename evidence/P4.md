# P4 — Stroke downgraded to one optional toy

**Goal (order §5 P4 / §4.4 / A10):** no default registration, one `stroke_toy` when
enabled, description says 玩法/演示, audit rows marked `mode:"toy"`.

## Implementation

- The toy no longer loads `dsh-stroke`. Since 2026-11-14 the stroke is drawn by
  `backends/toy-draw.js` through the same Win32 `SendInput` path the UIA backend uses
  (MIT; derived plumbing credited in `THIRD-PARTY-NOTICES.md`), so the plugin ships
  no unsigned binary and no unlicensed dependency (D3, now resolved).
- `backends/toy-draw.js` is imported **only** when `toyStrokeEnabled` is true
  (`index.js`: `if (config.toyStrokeEnabled) backends.toy = await createToyDrawer(...)`).
  Default → the drawer is never even constructed.
- The toy never takes a caller-supplied trajectory. It takes a shape name from a
  closed enum (`circle square triangle heart star wave`), a centre, a radius, a point
  count and a duration; the kernel generates the points and enforces
  `toyStrokeMaxPoints` twice (clamp at build time, hard reject afterwards).
- The button is released in a `finally`, and `stop()` aborts between points — a toy
  stroke can never leave the left button down (the lesson from D10).
- Same gate as every write, and the row carries `mode:"toy"` so toy usage can be
  counted separately from production actions.

## Stroke drawer on the real machine (`test/toy-live.mjs`)

```
node test/toy-live.mjs
{ "drawerOk": true, "uiaOk": true,
  "shapes": ["circle","square","triangle","heart","star","wave"],
  "circlePoints": 201,          ← one closed circle, 200 samples + closing point
  "closesOnStart": true,
  "startsAtRight": true,
  "clampedPoints": 400, "clampHonoured": true }
```

The DRAW call itself is **deliberately not fired**: a toy stroke is a real left-button
drag on whatever is under the cursor, which could select text or move a window on
someone's desktop. So the live check proves the drawer builds against the real Win32
API, the shape geometry and the hard cap; the gate + audit + injection wiring for the
toy is proven with the fake backend in `test/02-auth-invariants.test.mjs` (records 121
points, `backend:"toy-draw"`, `mode:"toy"`). This limitation is repeated in
`evidence/P6.md`.

## Measured (A10)
| Check | Result |
|---|---|
| default tool names | `hands_view, hands_act, hands_run, hands_status` — **0** stroke tools |
| default backend log | `toy=not loaded (toy off)` |
| with `toyStrokeEnabled: true` | **exactly one** `stroke_toy`, total 5 tools, 7,691 B |
| toy description | contains 玩法/演示 and 不是生产力 |
| toy parameters | `shape` is a 6-value closed enum; no `points[]`/`strokes[]` parameter exists |
| point cap | config 400 → circle drew 121 points (`test/02`, fake backend recorded `points: 121`); kernel rejects anything above the cap |
| audit | rows with `mode:"toy"`, `backend:"toy-draw"`; separate from production rows |

Toggle behaviour: tool presence is decided in `apply()`, so changing
`toyStrokeEnabled` restarts the plugin row (the same restart DSH performs for any
non-volatile config edit) and the tool appears or disappears. Both directions are
covered by `test/01-surface.test.mjs` (4 tools ↔ 5 tools).

## Licensing note (resolved)

The toy used to load `dsh-stroke`, which declares no license. Since 2026-11-14 it
draws in-repo through the MIT Win32 primitives, so no unlicensed dependency remains
(DEVIATIONS.md D3). `tools/check-repo.mjs` now reports **0 WARN** on runtime
prerequisites.
