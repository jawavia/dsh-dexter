**Goal (order §5 P6 / A13–A15):** license + third-party + security documents, a
README that states both allowed and forbidden uses, a static-only CI, and a private
repository first. **Nothing was published, pushed or uploaded** (R7: every external
action needs the human's explicit, per-instance permission).

## A14 — security documentation

`SECURITY.md` states, in order: local execution only / zero outbound traffic /
per-action authorization / the audit is **not** a security boundary / vulnerability
disclosure contact and what to include. It also lists what is out of scope (UIPI,
anti-cheat reactions, screenshot content, approval not being a sandbox, the toy), the
four rules the project holds itself to, and where data lives.

`README.md` now carries an explicit **Allowed and not allowed uses** section
(personal automation vs password/payment/OTP/third-party machines/unattended mass
actions) so the dual-use position is not implied by a slogan.

## A15 — CI

`.github/workflows/ci.yml` runs, on `windows-latest`, only:
`01-surface`, `02-auth-invariants`, `03-config-single-source`, `check-repo`, and the
surface measurement. The two suites that inject real input (`test/live-smoke.mjs`,
`tools/dual-run.mjs`) are deliberately excluded and documented as desktop-only.

`tools/ci-local.mjs` is the local stand-in: it validates the workflow's structure and
commands (structure keys, `windows-latest`, spaces-only indentation, every referenced
file exists, **no GUI suite listed**), then runs exactly those commands here.


**Not verified:** the workflow has never executed on GitHub, because no repository
exists and pushing is on hold by the human's standing rule (DEVIATIONS.md D11). Treat
A15 as *prepared and locally reproducible, not proven on a runner*.

## Publish state (deliberately not done)

- no git repository, no remote, no push, no npm publish, no release: R7 forbids any
  of those without the human's explicit per-action permission;
- name availability (`dsh-dexter`, `dsh-tactile` → 404) comes from the order's own
  check, not from this build;
- the plugin stays a **local directory bundle**: Plugin Manager installs it from
  disk, which is exactly how it was verified (a stand-in host applies the manifest).

## Before the first public release

1. run CI once on the real repository (A15) — and only after the human lifts the
   no-push rule (D11);
2. decide the install path for the legacy engines for a fresh user: the current
   three-way resolution (config / env / `local.config.json` / sibling package) works
   for a transition install but a first-time user needs a documented engine install;
3. sign nothing, ship no binaries, keep `os: ["win32"]`.

(Item "resolve the stroke license" is done: the dependency is gone — D3.)
