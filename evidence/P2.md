# P2 — One tool surface

**Goal (order §5 P2):** `hands_view` / `hands_act` / `hands_run` / `hands_status`;
writes only through `hands_act`; one read surface; old names gone.

## What each tool owns

| Tool | Surface | Notes |
|---|---|---|
| `hands_view` | 11 read actions: `info list focus capture zoom locate text read wait wait_window uia` | routed per action: pixel engine for the observation actions, UIA backend for `list`/`focus`/`uia` (with pixel fallback) |
| `hands_act` | `move click drag scroll type key hotkey` + `stop` | the only place any input capability exists at top level |
| `hands_run` | `steps[]` (same names), `resumeFrom`, `stopOnError`, `dryRun` | one human decision for the batch, one audit row per step |
| `hands_status` | `tail` | read-only |

## Design choices worth noting

- No hidden legacy aliases. The order allowed them "for one version"; a new bundle
  with a new name does not need a migration shim, and an alias is a second write
  entry by definition.
- The step schema inside `hands_run` repeats parameter names but not explanations:
  that is where the 2,006 B goes, and it is the price of a batch that stays
  self-describing without a second tool.
