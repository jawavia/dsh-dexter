**Goal (order §5 P5 / A4–A9, A7, A8, A9):** default per-action authorization, latched
only when bounded, stop revokes, human pause for every backend, one audit stream, one
config source. Every claim below is a line in a test that ran.

## A7 — no session by default, bounded session when opened (numbers adjustable)

Model after the 2026-11-14 rework (DEVIATIONS.md D12): a human opens a **session
grant** with minutes + action budget + rate cap; without one, every write asks once.

| Check | Result |
|---|---|
| default | `askOnWrite=true`, no session; 2 writes → 2 approval requests |
| session numbers | come from settings (`armMinutes=30`, `armActions=200`) unless the human types their own (`/dexter arm 45m 300`) |
| 2-action session | 2 writes with 0 prompts; the 3rd asks again |
| audit | each session write logged as `session:1/2`, `session:2/2`; the 3rd as `ask` |
| expiry | a 1-minute session is gone after 61 s (`grant-expired` audited) and the next write asks |
| extend | an exhausted session can be extended (`grant-extended`), then writes run again |
| rate cap | `maxActionsPerMinute=3` → the 4th write in a minute is refused (`频率上限`) and audited; after the window it runs |
| `Ctrl+Alt+F12` | opens a session using the configured numbers; one write spends it with **0** prompts |
| `Ctrl+Alt+F11` / `Esc` | stop, and the next write is refused |

**Permanent target rules (new, and not configurable):**

| Check | Result |
|---|---|
| click into the 注册表编辑器 window with a session open | **refused** ("永久禁止"), **0** injections recorded, audit row `system-target` |
| `type` while 注册表编辑器 is the foreground window | refused |
| click into the 微信 window with a session open | one approval request, row `ask:sensitive` |
| the human says no to a sensitive target | nothing injected |

**Free hover (方案 C, D13):**

| Check | Result |
|---|---|
| no session, no approval service | a `move` still runs: approval `hover(free)`, audited, no prompt |
| any mouse button held | refused (`button-held`) — a move with a button down is a drag |
| system target | still permanently refused |
| session credit | not consumed (a 1-action session still has its action after a hover) |
| click with no authorization | still refused |
| live install (2026-11-14) | `seq=44 move executed approval=hover(free) verify=foreground:ok`; a following click was rejected by the approval service |

**Why `move` is still gated:** with no session, a hover asks like any other write; inside
a session it costs one action from the budget. The deliberate difference from the old
engine is recorded as D7 (`tools/rule-probe.mjs`).

## A8 — stop revokes, and the next write is refused

| Check | Result |
|---|---|
| write before stop | allowed |
| `kernel.stop()` then a write | refused, text names the stop and the recovery path |
| audit | `decision:"stop"`, `approval:"revoked"`; the refused write is `decision:"denied"` with the stop reason |
| agent-side `hands_act action=stop` | revokes only; a following write is still refused |

**Defect found and fixed by the live test:** the stop check used to live *after* the
human-pause wait, so on a desktop where a human had just typed, a stopped plugin
waited for idle and then executed the write. `kernel.js` now evaluates
`#stopDenial()` before the pause wait in both `act()` and `run()`; re-run: live
`stopRefusesNextWrite = true`.

## A9 — human activity suspends every backend

| Check | Result |
|---|---|
| controlled probe (unit) | a key press suspends injection; the write is refused while suspended |
| suspend + resume audited | `tool:"human"`, `decision:"suspend"` / `"resume"`, with the reason and idle time |
| resume after idle | `humanIdleResumeMs=2000` → back to normal, next write allowed |
| live, documented hook | suspend detected in **59 ms** |
| live, real key press (child process holds shift) | suspend detected in **434 ms** |
| live, write during the suspend | waited 2,338 ms for idle, then ran; the `resume` row has a lower `seq` than the executed row — the order of events is provable from the trail |
| live, our own 20 moves | **0** spurious suspend rows |

Polled detection, not a keyboard hook: 150 ms cadence, so the worst case is ~150 ms
after the key goes down. Stated in DEVIATIONS.md D6.

## A6 — one configuration source

`test/03` proves the schema defaults and the runtime defaults come from the same
`FIELD_SPEC`, that unknown keys are dropped, that out-of-range values clamp, and that
nothing reads or writes `config-overrides.json`. The live status line prints the
effective values (`mode=per-action armTtl=120s readOnly=false verify=foreground …`),
so what the settings page says and what runs is the same object.

## Misuse cases exercised

| Attempt | Result |
|---|---|
| write with no approval service and no grant | refused (fail-closed) with the recovery path |
| agent asks for `action=stop` then writes | still refused |
| `dryRun: true` on a write | nothing injected, no approval consumed, `decision:"dry-run"` row |
| latched requested without bounds | refused / downgraded, visible in the result |
| unknown capability | rejected by argument validation, no backend call |
| points above `toyStrokeMaxPoints` | rejected before any helper call |
