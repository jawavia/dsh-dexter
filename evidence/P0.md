# P0 — Baseline and measurement scripts

**Goal (order §5 P0):** measure before changing anything; export the old package's tool
count / bytes / call statistics and bind every later acceptance check to those numbers.

## Delivered

| File | Role |
|---|---|
| `tools/surface-harness.mjs` | boots a plugin's `apply()` with a stand-in Cordis context and records every `ctx.tools.register(def)`; data dirs redirected to a scratch tree so measuring cannot touch a real trail |
| `tools/measure-surface.mjs` | the old baseline metric, applied to any definition set (`legacy` \| `dexter`) |
| `tools/audit-stats.mjs` | one reader for all four audit formats (pixel / control / stroke / dexter) with hash-chain sanity counts |
| `baseline/new.json` | the sanitized numbers every later check compares against |
| `baseline/local/*` | full raw measurements (git-ignored: they contain machine paths) |

## Commands actually run (2026-11-14)

```
node tools/measure-surface.mjs legacy "<old package dir>" --out baseline/local/legacy-remeasured.json
node tools/audit-stats.mjs all --json baseline/local/audit-stats.json
```

## Result 1 — tool surface reproduces the recorded baseline

| Source | tools | total | pixel | control | stroke |
|---|---|---|---|---|---|
| `tools/baseline.json` (recorded 2026-11-08) | 25 | 35,201 B | 20,370 | 12,145 | 2,686 |
| `measure-surface.mjs` (this run) | 25 | **35,174 B** | **20,370** | 12,118 | **2,686** |

pixel and stroke reproduce **byte-exactly**. The six control tools differ by 29 B in
total because the old estimator wrapped control's bare parameter map slightly
differently (+29 B params, −2 B output). The recorded 35,201 B stays the comparison
target, so a later A2 claim is conservative.

**Write-call share:** pixel 863 attempts, control 130 allows, stroke 2 → **86.7 % / 13.1 % / 0.2 %**.
That is the same picture the order describes ("pixel ≈ 86 %").

**One honest adjustment (DEVIATIONS.md D9):** the order's "769 attempts" is not the
live file alone (285). It matches live + the 2026-11-07 sealed generation
(285 + 479 = 764). No conclusion depends on it: the 86.7 % share holds across all
generations, and the decision (keep pixel, rewrite the kernel, downgrade stroke) is
unaffected.

## Result 3 — what the harness can and cannot measure

- It measures **registration**, so A1/A2/A3/A10 come from the same code path the host
  uses (`apply()` → `ctx.tools.register`), not from a copy of the definitions.
- It does **not** prove the model sees these tools; the live check for that is the
  apply-time log line (`[dexter] ready: 4 tools [...]`) plus `hands_status`.
- Registration is asynchronous here (backends are dynamic imports), so the harness
  waits for the registration set to stop growing instead of guessing a delay.
